# mlch

**mlch is the app; mulch is the thing.** Everywhere the app's name shows (app and window name, menus, dialogs, folders like `~/Documents/mlch`, the domain mlch.app, the repo, `MLCH_*` env vars, `~/.mlch`, globals, headers, CSS class prefixes, the agent's MCP server) it is lowercase **mlch**, said "mulch". The thing you create is barely named in the interface ("New", titles, "This one / All"); in code it is a `Mulch` (`mulchId`, `/api/mulches`, `search_mulch`), and the agent calls it "the canvas".

Voice-first thinking canvas. Mac app: Next.js 16 inside Electron, AI on the user's own Claude Code / Codex subscription. Product vision: README.md. V1 plan and status: docs/PLAN.md. Current plan (a small public release, with checks): docs/PLAN-3.md; before it, docs/PLAN-2.md (call to shared link). What comes next: docs/ROADMAP.md (delete items when they ship). Investigations: docs/research/.

## Commands

- `npm run check`: typecheck, lint, vitest, electron tests. Run before committing.
- `npm run dev`: browser dev server on :3100. Set `MLCH_LIBRARY=<dir>` to keep test data out of `~/Documents/mlch`.
- `scripts/scenarios/*.cjs`: app scenarios for `electron-run` (checks from PLAN-2 and PLAN-3).
- `npm run electron:dev` / `npm run app`: desktop app (dev / production build).
- `npm run release -- [--channel beta|latest] [--notes …]` (official release: checks, build, sign and notarize the app and the DMG, smoke test, Gatekeeper checks, upload to R2, tag, GitHub release; `--promote` moves beta to latest; checklist in docs/RELEASING.md) / `npm run dist` (signed, official) / `npm run dist:unsigned` (a build from source: no updates, its own name and profile, `mlch dev`): the packaged app in dist/. `build.json` in the staged app says version, commit and whether it is official. `scripts/package-app.mjs` stages build/app (Next standalone output plus the traced Electron side and search worker, `cli.json` with the tested CLI versions); electron-builder.yml packages it; `build/after-pack.cjs` copies node_modules and Turbopack's links. Test a staged app with `electron-run --app build/app`, but run a packaged app outside the repo (the repo's node_modules would supply the CLIs).
- `node scripts/electron-run.cjs <test.cjs> [--library dir] [--shots dir] [--fake-mic file.wav] [--production]`: drive the real app with Playwright (throwaway profile). `scripts/electron-shot.cjs <out.png> [route]` for a screenshot. electron-run fails if a new Electron crash report appears in ~/Library/Logs/DiagnosticReports.

## Architecture

- The mulch screen: the canvas, the conversation panel on the right (`Conversation.tsx`: what was said or typed and what became of it via jobs' `inputIds`, the AI's messages from `tell`, results, the call; ⌘J; opens for a new message or a call), opened cards on the left (`SidePanel.tsx`, editable). Mulches are archived, not deleted, from the list (`archived.json`); deleting from the archive turns off its share links.
- `src/lib/mulch/`: the document. A mulch changes only through ops (`types.ts` MulchOp), applied by the pure `ops.ts` on both sides. `store.ts` (server) holds open mulches, logs batches to `events.jsonl`, saves `mulch.json`, broadcasts over SSE. `client.ts` (browser) mirrors it, applies the user's ops optimistically, keeps undo (inverse ops). `place.ts` is all geometry. `history.ts` checkpoints.
- mlch is an interface on the person's own Claude Code or Codex: their CLAUDE.md / AGENTS.md, MCP servers, claude.ai connectors and plugins apply in mlch (Settings → AI can turn this off). mlch overrides only billing (the subscription; an API key in the CLI's settings is ignored unless chosen in Settings) and what the AI does unasked (connector tools that act ask with a card). docs/research/connectors.md.
- `src/lib/agent/`: `server/` is node-banana's harness (Claude Agent SDK, codex app-server, billing guard), kept close to upstream. `tools.ts` = mulch tools; `prompts.ts` = per-lane prompts; `jobs.ts` = per-mulch lanes (fast capture, slow enrichment, quick instructions, ingest) plus long work (making, research: at most 2 per mulch, 3 in all). The person's instructions and long work are kept in `<mulch>/jobs.json` (unseen results, failures, retry; ones running at quit come back failed). A long job holds space on the canvas (`holdSpace` in place.ts) where its result lands and where the canvas draws it in progress. Main shows a notification when the person's own work finishes (done or failed, any length) or a connector card waits, unless they are looking at that mulch, badges the Dock with unseen results, and asks before quitting while work runs.
- `src/lib/ingest/`: files and links into assets/ (content-addressed, extracted text beside them). `place.ts`: pictures (described), documents (read), recordings (played, transcribed on this Mac or by Groq), links (read), YouTube/Vimeo links (`video.ts`: played in place after a click; with a Gemini key, `media/gemini.ts` watches YouTube for a summary and transcript), links straight to a file (downloaded as that file). `fetchFile.ts` downloads for the AI's `add_file` and file links: https only, never local addresses, type and size limits.
- Media: fal models; `src/lib/media/picks.ts` holds the recommended model per task (checked each release with `scripts/fal-picks.mjs`), listed first by `media_search`.
- Home (`components/home/HomeList.tsx`): the list by when (opened counts), search filters titles, then hits inside mulches and linked folders.
- Sharing: Settings → Sharing (`settings.sharing`, `src/lib/share/account.ts`, `components/settings/Sharing.tsx`, also a setup step): mlch.app (Google sign-in, $12/year Stripe subscription to make new shares; lapsed: old links keep working), off (no Share buttons), or the person's own server (address + key; `cloud/` deployed with `npm run deploy:own`, guide at mlch.app/server). Sign-in: the server keeps a verifier, the browser comes back via mlch://signed-in, main posts the grant to `/api/account`, the session goes to Keychain through main (bridge `account-token`). `cloud/` is the Cloudflare Worker on mlch.app (the landing page is the app's canvas with nothing behind it, `cloud/viewer/Landing.tsx`; legal pages; /download; /admin behind Cloudflare Access with friend codes, accounts and account deletion) and share.mlch.app (shared things on their own origin): capability links, accounts only for making shares (`cloud/src/accounts.ts`, D1; `wrangler.mlch.jsonc` is mlch.app, `wrangler.jsonc` an own server with SERVER_KEY), files in R2 served with the artifact sandbox, one Durable Object per shared canvas that numbers the owner's op batches and relays them to viewers (multi-writer later). The viewer reuses the app's canvas components read-only. `src/lib/share/client.ts` talks to it; `shares.ts` shares a canvas (live: every applied batch follows, new files first; a link card goes as what it links to, an ordinary card, one step deep) or one made file, each share on the server it was made on, keeps owner tokens in `<mulch>/shares.json`, and imports a shared canvas as a new mulch (`mlch://open?share=<manifest>` → `/open`). Shared links carry link previews (the Worker adds og tags; preview.png is the canvas as shared or a made file's first page). Made files open in a frame page with Full screen (`cloud/src/frame.ts`). App updates are served from R2 `releases/mac/` (`scripts/release.mjs`). mlch.app/admin (`cloud/src/admin.ts`, behind Cloudflare Access, m38.ai): friend codes (Stripe coupons, Checkout accepts them, the webhook refuses discounts not ours), accounts, deleting an account. Legal pages: `cloud/landing/legal/`. API and deploy: cloud/README.md.
- `src/lib/artifacts/`: files the AI makes, in the mulch's `artifacts/`. HTML is served with a sandboxing CSP (opaque origin, no network) and shown full-window over the canvas. HTML is a deck or a page (`artifactKind`, `<meta name="mlch:kind">`): the AI writes a deck's slides only and `deck.ts` adds the player (1920×1080 scaled, one slide, keys, click, swipe); viewers size by kind. `preview_artifact` (main renders it off-screen) checks every slide, or a page at desktop and phone width. What the AI makes follows the house style (Settings, Style), which starts as mlch's own look (`DEFAULT_HOUSE_STYLE` in prompts.ts, editable, "made with mlch"); `{{file:mlch:fonts/…}}` embeds the app's fonts. `pptx.ts` is the quick template builder; real decks and documents come from the maker lane.
- Maker lane (`submitMake` in jobs.ts): Claude Code with its own tools inside its OS sandbox (`workspace` in HarnessTurnParams → `sandbox` + permission rules in claudeHarness.ts), or `codex exec` in workspace-write (codexExec.ts). Writes only to `<mulch>/work` and `<mulch>/artifacts`; network only to package registries (Claude). New files in artifacts/ become cards.
- `src/lib/search/`: one SQLite index for the library (`<library>/.index.sqlite`, `node:sqlite` with FTS5) plus local embeddings (multilingual-e5-small) in a WebAssembly worker thread (`scripts/embed-worker.mjs`, onnxruntime-web). Search merges keyword and vector rankings, never waits more than 8s on the model, and works keyword-only without it. `exa.ts` is the optional Exa web search.
- Research lane (`submitResearch` in jobs.ts): many searches and page reads, then sources, a comparison table and a write-up; resumes the session once if outputs are missing.
- Logging: `src/lib/log.ts` writes JSON lines to `<logs>/mulch.jsonl` (redacted, rotated); main writes `desktop.log` and records process crashes; crash dumps stay local. Settings → Diagnostics saves a support report to ~/Downloads.
- File reading for instructions: read-only, home folder, private places refused (`src/lib/agent/files.ts`).
- Links and sources: a `ref` node is a link card to an item in another mulch or a file in a linked folder, read live (`src/lib/links/`: resolve, backlinks, Bring here). Linked folders (Settings → Sources, `src/lib/sources/`) are indexed into the library index under `src:<id>` and watched; Obsidian vaults keep links, tags and frontmatter. Enrichment and research get the best hits elsewhere in their prompt (`relatedElsewhere` in jobs.ts) and link with a stated reason (`link_to`). Sources set to "Only when asked" are searched only for the person's own instructions.
- Calls: `/api/mulches/:id/call` turns on call capture (jobs.ts `setCallMode`): speech is gathered for `CALL_BATCH_MS`, the mic's echo of the others is dropped (`voice/echo.ts`), and the call prompt captures it as conversation ([me]/[them]; only [me] can instruct). Instructions and making get the conversation (`callTranscript`). The menu bar (main.cjs `createTray`) has New, New Call (⌃⌘L), recent mulches and Stop Listening.
- `src/lib/voice/`: browser recorder (WAV chunks cut at the end of speech; `vad.ts` is Silero VAD on onnxruntime-web, model in public/vad, runtime served by /api/vad; loudness as the fallback) and server transcriber (Groq, or local per Settings). Spoken instructions wait for 4 s of quiet (jobs.ts `submitSpokenCommand`); holding ⌥ (`HoldToTalk.tsx`) makes speech one instruction. `local.ts`: local transcription and system audio capture through the native helper (chunks become speech from "them"; the mic is "me" while one runs).
- `native/mlch-audio/`: Swift helper binary (Parakeet via FluidAudio on the Neural Engine; Core Audio process tap for the Mac's sound output), JSON lines over stdio, started by main (`electron/lib/audio-helper.cjs`, restarted once after a crash) and reached through the bridge's `audio` request. Build with `node scripts/build-native.mjs [--test]` (uses a swift.org toolchain from ~/Library/Developer/Toolchains when present). Model in ~/Library/Application Support/mlch/models.
- The packaged app ships no Claude Code or Codex: `src/lib/agent/server/cli.ts` uses the person's install when at least the tested version (found in ~/.local/bin, Homebrew and similar; Finder gives apps no shell PATH), else downloads the tested version (npm tarball, lockfile hash, Anthropic / OpenAI Team ID) to ~/Library/Application Support/mlch/cli, only for the AI in use or when asked. A CLI failure on an install switches to the tested copy.
- `electron/`: shell adapted from node-banana. Main injects a per-launch token; keys live in Keychain via safeStorage and reach the server process over parentPort, never through the page.

## Design

Black marker on a clean napkin, with one amber highlighter. Tokens live in `src/app/globals.css` (`:root`, exposed to Tailwind via `@theme`); use them, not raw colours.

- **Type:** Schibsted Grotesk for everything (`--font-ui`). The logo's hand lettering appears only as the wordmark (`public/brand/wordmark.svg`); Barriecito (`--font-scribble`) is loaded for it and used nowhere else. Sentence case, no all-caps labels, no middle dots between items.
- **Colour:** paper `#FCFCFA` (canvas), chrome white (cards, floating panels), ink pure black at three strengths (`ink`, `ink-2`, `ink-3`), hairlines (`line`, `line-2`). Amber `#FFC000` only as a fill, never text: New, recording, selection, focus pulse, things that need you. Tints for kinds: `amber-soft` the person's post-it notes, `blush` questions, `mist` definitions, `sage` examples. `danger` for errors and failures.
- **Cards:** the person's own words (origin `user` / `speech:*`, or touched) carry a 1.5px ink outline; AI material sits on a hairline or its tint. Typed notes are tilted yellow post-its. Kind labels are small, lowercase, `ink-3`. Selected: amber outline.
- **Connections:** soft cubic curves bowing to one side (`FloatingEdge.tsx`); the person's solid, the AI's dotted; labels on paper chips, shown only when they fit.
- **Chrome:** the canvas is full-bleed; controls float over it in white `.float` panels (hairline, soft shadow, rounded-xl/2xl). Primary buttons black, the one creative action amber.
- **The scribble** (from the logo, `components/brand/Scribble.tsx`) is the only animated motif: drawn while listening (moves only while you speak), looping wherever the AI is working (job control, placeholder card, mulch list), faint and still on an empty canvas. Nowhere else.
- **Motion:** only to show a change: cards entering, the focus pulse, the scribble. Respect reduced motion.
- `scripts/brand-assets.mjs` rebuilds the icon, wordmark and scribbles from `design/mlch-logo.svg`.

## Rules

- UI copy: plain functional words only, no taglines or chatty lines. Ask George for any sentence-level wording.
- The AI never gives coordinates; it says `near`, `place.ts` decides. The LLM decides grouping, code decides geometry.
- The AI never edits, moves or removes what the person made, said or touched (origin `user` / `speech:*`, `userTouched`) unless an instruction allows it (`allowUserEdits`).
- Tool errors returned to the model say what is allowed, not just what failed.
- Every mulch change goes through ops so it is logged, undoable and in history.
- Dates shown with a time.
- No native ML runtimes inside Electron processes (onnxruntime-node crashes them with EXC_BREAKPOINT); use WebAssembly. Built-ins the bundler does not know (`node:sqlite`, `node:worker_threads` with a file) are loaded with `process.getBuiltinModule`.
- Log with `log.info/warn/error(area, msg, { mulchId, jobId, … })`, not console.
- Never give the agent an unsandboxed shell. Native tools only through `workspace` (OS sandbox).
- Anything the AI generates and the app renders (HTML artifacts) is untrusted: sandboxed origin, no network, no navigation. The desktop server refuses API requests from foreign pages.
- Code adapted from node-banana keeps its MIT notice (THIRD_PARTY_NOTICES.md and file headers).
